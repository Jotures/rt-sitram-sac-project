# Registro de decisiones DEC-016 a DEC-020

## DEC-016 — Supabase CLI local versionado y migrations-first

- **Fecha:** 2026-08-13
- **Sesión:** SESSION-20260813-008
- **Estado:** Accepted
- **Ámbito:** Backend local y persistencia
- **Reemplaza a:** ninguna decisión
- **Reemplazada por:** ninguna decisión
- **Rutas afectadas:** `implementation/package.json`, `implementation/pnpm-lock.yaml`, `implementation/supabase/`

### Contexto

El Technical Spike requiere una base Supabase/PostgreSQL reproducible antes de introducir PowerSync. No existe todavía un proyecto remoto ni datos de dominio, por lo que el esquema debe poder reconstruirse localmente y mantenerse bajo el límite `implementation/`.

### Decisión

El Supabase CLI oficial se distribuye como dependencia de desarrollo fijada del workspace (`supabase@2.114.0`) y los comandos locales se ejecutan mediante pnpm. La configuración queda exactamente en `implementation/supabase/`, con `config.toml` y migrations SQL versionadas, y estado temporal ignorado.

Los cambios PostgreSQL se realizan migrations-first: una migration ordenada es la fuente de verdad del esquema. `supabase db reset` reconstruye la base local aplicando migraciones y, si se introduce posteriormente, seed técnico versionado. No se enlaza ni crea ningún proyecto remoto en este flujo.

### Justificación

El CLI oficial admite instalarse como dependencia de proyecto y requiere Node.js 20 o superior en esa modalidad. El flujo oficial identifica `init`, `start`, migrations y `db reset` como camino local reproducible, y reserva `.temp/` y `.branches/` para estado no versionable.

### Consecuencias

- Docker Desktop o un runtime compatible con daemon accesible es un prerrequisito externo para ejecutar el stack.
- `config.toml` no contendrá secretos; cualquier secreto futuro se referenciará con `env()` desde un archivo ignorado.
- Las modificaciones realizadas en Studio solo son aceptables si se capturan y revisan en una migration antes de integrarse.
- La siguiente sesión puede usar la tabla técnica temporal, pero todavía debe configurar PowerSync de forma independiente.

### Alternativas consideradas

- Instalación global del CLI.
- Crear un proyecto Supabase remoto de forma automática.
- Mantener esquema solo en Studio o en SQL no versionado.
