# SESSION-20260813-009 — PowerSync y sincronización experimental básica

## Estado

In progress — seguimiento autorizado por el usuario

## Objetivo

Integrar PowerSync y SQLite y validar sincronización experimental básica.

## Trabajo realizado

- Se confirmó la integración vigente de PowerSync Web, SQLite/WASM administrado, Supabase Auth, Sync Streams edición 3 y cola de uploads.
- Se añadieron `@powersync/web`, `@powersync/react` y `@journeyapps/wa-sqlite`; el schema local contiene exclusivamente `spike_records`.
- Se creó una instancia PowerSync Cloud **Development** en el plan gratuito, conectada a Supabase mediante un rol de replicación sin contraseña versionada.
- Supabase Auth usa JWKS y audiencia `authenticated`; el Sync Stream desplegado filtra por `owner_id = auth.user_id()`.
- El connector obtiene el token vigente de Supabase y sube INSERT/UPDATE/DELETE mediante el cliente existente; RLS conserva la autoridad final.
- `disconnectAndClear()` se ejecuta antes del primer usuario, logout y cambio de identidad.

## Validación

- SQLite quedó `Ready` y PowerSync `Connected` con USER A y USER B.
- USER A insertó localmente con render inmediato; el registro llegó a PostgreSQL y un cambio remoto volvió a SQLite.
- UPDATE y DELETE locales llegaron a PostgreSQL.
- USER B no recibió A, creó y sincronizó B; al volver a USER A, B no fue visible.
- El logout limpió SQLite antes del siguiente login; no se usó filtrado de UI como sustituto.
- `pnpm install --frozen-lockfile`, format, typecheck, lint, 18 tests y build finalizaron correctamente.
- `.env.local` permanece ignorado, no hay secretos versionados y `git diff --check` es correcto.

## Seguimiento — persistencia offline y reconexión

- Se detectó que el ciclo previo ejecutaba `disconnectAndClear()` cuando Auth estaba todavía en `INITIALIZING` y también al reconstruir el ciclo en cada arranque; ambos casos impedían demostrar persistencia al cerrar/reabrir.
- El provider ahora espera la restauración de Auth. El ciclo conserva SQLite solo si un marcador local no empresarial coincide con el UUID de la sesión restaurada. Sin marcador, con identidad distinta o al logout, limpia SQLite antes de conectar.
- Se añadieron pruebas unitarias para el arranque de la misma identidad, la limpieza segura ante identidad desconocida/cambio/logout y la espera de resolución de Auth.
- `pnpm format:check`, `pnpm typecheck`, `pnpm lint`, `pnpm test` (10 archivos, 20 pruebas) y `pnpm build` finalizaron correctamente; `git diff --check` no reportó errores.
- El artefacto PWA de producción abrió con `PWA: Ready` y la configuración pública de Supabase presente. La prueba manual real continúa pendiente porque no hay una credencial de usuario técnico disponible para esta sesión y debe incluir corte de red real, no solo el indicador visual de conectividad.
