## Investigación Just-in-Time

- [vite-plugin-pwa](https://github.com/vite-pwa/vite-plugin-pwa) es mantenida y MIT, pero su peer dependency publicado no declara Vite 8. Su [issue de compatibilidad](https://github.com/vite-pwa/vite-plugin-pwa/issues/923) confirma que el soporte aún estaba en trabajo. No se forzó esa integración.
- [Chrome](https://developer.chrome.com/docs/lighthouse/pwa/installable-manifest) requiere manifest con nombre/short name, start URL, display admisible e iconos 192 y 512 para instalabilidad. [web.dev](https://web.dev/articles/add-manifest) recomienda fallback ráster; se usan PNG.
- `@supabase/supabase-js` vigente comprobado: 2.110.8, licencia MIT. [Supabase](https://supabase.com/docs/guides/auth/choosing-a-server-package) recomienda el cliente base para una SPA sin SSR/cookies. [La guía React](https://supabase.com/docs/guides/auth/quickstarts/react) usa `VITE_SUPABASE_URL` y `VITE_SUPABASE_PUBLISHABLE_KEY`.
- [API Keys](https://supabase.com/docs/guides/getting-started/api-keys): publishable keys `sb_publishable_...` son públicas; `anon` sigue como clave legacy compatible. Secret/service_role son solo backend y no aparecen en `VITE_*`.
- [Supabase Auth JavaScript](https://supabase.com/docs/reference/javascript/auth), [onAuthStateChange](https://supabase.com/docs/reference/javascript/auth-onauthstatechange) y [signOut local](https://supabase.com/docs/reference/javascript/auth-signout) fundamentan persistencia, suscripción y alcance de logout.

## Trabajo y archivos

- Se añadieron manifest, iconos PNG de 192×192 y 512×512, registro de `/sw.js` solo en producción y app shell cacheado con network-first/fallback. Cache Storage solo contiene HTML, JS, CSS, manifest e iconos.
- `src/lib/network/` expone el estado UX `ONLINE`/`OFFLINE` a partir de navegador y sus eventos, sin autoridad sobre operaciones empresariales futuras.
- Se añadió solo `@supabase/supabase-js@2.110.8`; la capa `src/lib/supabase/` valida configuración tipada y contiene el único `createClient()`.
- `src/features/auth/` contiene provider/hook con estado inicial, restauración de sesión, observación, email/password y logout local. No existe signup público.
- Se actualizaron `implementation/README.md`, DEC-014, DEC-015, los índices de sesiones/decisiones y este log.

- La abstracción de conectividad tiene prueba de `offline`→`OFFLINE`, `online`→`ONLINE` y limpieza de listeners. El navegador de validación no expone throttling de red; detener solo el host local conserva `navigator.onLine`, que es coherente con su condición de señal UX.
- Se comprobó antes de build que no existían variables Supabase reales en el entorno ni archivos `.env` privados. `.env.example` contiene solo placeholders y no se registraron secretos.

## Decisiones

- DEC-014 — Shell PWA estándar sin integración Vite adicional.
- DEC-015 — Cliente Supabase SPA encapsulado y Auth local por dispositivo.

## Limitaciones

- **Supabase remote authentication pending real project credentials.** No hay URL ni publishable key reales en el entorno; por tanto login remoto, persistencia tras login y logout contra un proyecto Supabase no se probaron.
- Una sesión local cacheada puede restaurarse conforme al SDK, pero no se representa como identidad verificada por servidor ni autorización RLS sin red.
