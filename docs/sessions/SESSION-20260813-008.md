# SESSION-20260813-008 — Supabase local foundation y Auth real local

## Estado

Completed with external blocker

## Objetivo

Inicializar un backend Supabase local reproducible y validar Auth real local antes de configurar PowerSync. El alcance excluye Storage, PowerSync y dominio de negocio.

## Investigación Just-in-Time

- [Supabase CLI Getting Started](https://supabase.com/docs/guides/local-development/cli/getting-started): CLI como dependencia de proyecto, Node 20+, `init` y `start`.
- [Supabase local development workflow](https://supabase.com/docs/guides/local-development/cli-workflows): `config.toml`, migrations y seed versionables; `.temp/` y `.branches/` ignorados; `db reset` reproducible.
- [Supabase CLI config](https://supabase.com/docs/guides/local-development/cli/config) y [config/secrets](https://supabase.com/docs/guides/local-development/managing-config): Auth local en `config.toml`; secretos mediante `env()` no versionado.
- [PowerSync client identifiers](https://docs.powersync.com/sync/advanced/client-id) y [RLS and Sync Streams](https://docs.powersync.com/integrations/supabase/rls-and-sync-streams): UUID `id` y RLS por propietario no presentan impedimento evidente para el siguiente spike. PowerSync no se configuró.

## Trabajo realizado

- CLI `supabase@2.114.0`, DEC-016 y scripts de pnpm para start/stop/status/reset.
- Infraestructura inicializada directamente en `implementation/supabase/` mediante `--workdir`; no queda una ruta `implementation/supabase/supabase/`.
- Auth email/password activo, confirmación de email desactivada para desarrollo, signup público desactivado y URLs Vite permitidas. Storage está deshabilitado.
- Migration única `20260813094000_create_technical_spike_records.sql`: `spike_records` es **THIS IS TECHNICAL SPIKE DATA. NOT A PRODUCTION DOMAIN CONTRACT.** Tiene UUID `id`, `owner_id`, valor y timestamps; RLS limita CRUD al propietario `auth.uid()`.
- Scripts interactivos seguros para crear usuario técnico ficticio y comprobar que un usuario B no lee el registro experimental de A. No se guardan ni imprimen contraseñas.
- README actualizado. No se generaron tipos TypeScript: no existe aún consumidor de consultas; se documentó `supabase gen types --lang typescript --local` como generación futura automática.

## Validaciones

- `pnpm install --frozen-lockfile` correcto; lockfile reproducible. La descarga del binario opcional Windows reintentó y falló en este host, pero el binario oficial de `2.114.0` se comprobó directamente.
- `pnpm format:check`, `pnpm typecheck`, `pnpm lint`, `pnpm test` (5 archivos/9 tests) y `pnpm build` correctos.
- `supabase status` bloqueado de forma esperada por Docker/Podman ausentes.
- Stack, Postgres, Auth, reset, generación local de tipos, usuario, login E2E, reload, logout, prueba negativa y RLS en ejecución no se pudieron realizar sin daemon Docker.
- Seguridad estática: `.env*`, `.temp/`, `.branches/` y certificados ignorados; sin `SERVICE_ROLE_KEY` ni secret keys bajo `VITE_*`; migration/scripts sin claves ni contraseñas fijas; `git diff --check` correcto.

## Datos de usuario de prueba

No se creó un usuario porque Auth local no pudo iniciar. El script solicita credenciales técnicas ficticias en tiempo de ejecución, no las versiona ni registra la contraseña. No se usaron datos de empleados.

## Decisiones

- DEC-016 — Supabase CLI local versionado y migrations-first.

## Bloqueo y handoff

El único bloqueo externo es Docker Desktop o un runtime Docker-compatible con daemon accesible. El propietario debe disponer de Docker Desktop o proporcionar un proyecto Supabase remoto para continuar las validaciones de stack/Auth. No se creó un proyecto remoto automáticamente.

Tras resolverlo: iniciar el stack, configurar `apps/web/.env.local` con URL y clave pública local, crear dos usuarios técnicos ficticios, ejecutar la prueba RLS y probar login, recarga, contraseña errónea y logout. Solo entonces la siguiente sesión será **PowerSync + SQLite — sincronización experimental mínima**.
